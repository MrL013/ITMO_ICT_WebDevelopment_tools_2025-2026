# Лабораторная работа 3. Упаковка FastAPI приложения в Docker, Работа с источниками данных и Очереди

В этой лабораторной работе объединены и адаптированы результаты `lab1` и `lab2` в самостоятельный проект `lab3`.

## Цель работы

- упаковать FastAPI приложение в Docker
- вынести парсер в отдельный сервис
- связать парсер с PostgreSQL базой данных
- вызывать парсер из основного FastAPI приложения по HTTP
- вызывать парсер асинхронно через очередь `Celery + Redis`

## Что реализовано

- перенесено основное FastAPI приложение из лабораторной работы 1
- перенесена логика веб-парсинга из лабораторной работы 2
- добавлен отдельный контейнер с FastAPI-сервисом парсера
- добавлен endpoint синхронного вызова парсера из основного API
- добавлен endpoint асинхронного вызова через Celery
- добавлен Redis как брокер задач и backend результатов
- настроен `docker-compose.yml` для запуска всех сервисов
- подготовлены PowerShell-команды для проверки работоспособности

## Сервисы проекта

- `api` — основное FastAPI приложение Travel Buddy
- `parser` — отдельный FastAPI-сервис для парсинга URL
- `celery_worker` — фоновый worker для выполнения задач парсинга
- `db` — PostgreSQL база данных
- `redis` — брокер сообщений и backend результатов Celery

## Структура lab3

- `app/` — основное приложение FastAPI
- `parser_service/` — отдельный сервис парсера
- `alembic/` — миграции базы данных
- `docker-compose.yml` — оркестрация контейнеров
- `Dockerfile.api` — контейнер основного API
- `Dockerfile.parser` — контейнер сервиса парсера
- `.env.example` — пример переменных окружения
- `test_main.http` — примеры HTTP-запросов

## Основные сценарии работы

- пользователь обращается к стандартным endpoint-ам Travel Buddy API
- пользователь вызывает `POST /api/v1/parser/parse`, а основное API передаёт запрос сервису парсера
- пользователь вызывает `POST /api/v1/parser/parse-async`, а задача отправляется в очередь Redis
- `celery_worker` забирает задачу из очереди и сохраняет результат в базу данных
- пользователь проверяет статус фоновой задачи через `GET /api/v1/parser/tasks/{task_id}`

- синхронный HTTP-вызов парсера
- прямой вызов отдельного парсер-сервиса
