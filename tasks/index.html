Задания¶

Задача 1. Сравнение threading, multiprocessing и asyncio¶

В task1 реализованы три отдельные программы:

  • threading_sum.py
  • multiprocessing_sum.py
  • async_sum.py

Каждая программа:

  • содержит функцию calculate_sum()
  • делит диапазон на несколько частей
  • считает частичные суммы параллельно
  • объединяет результат
  • измеряет время выполнения

Особенность реализации¶

Сумма от 1 до 10_000_000_000_000 считается не прямым циклом, а через формулу арифметической прогрессии:

sum = (start + end) * count // 2

Это сделано для того, чтобы задача завершалась за разумное время и позволяла сравнивать накладные расходы разных моделей параллелизма.

Ожидаемый результат¶

Итоговая сумма:

50000000000005000000000000

Наблюдение по результатам¶

  • asyncio и threading оказываются быстрее в такой постановке
  • multiprocessing работает медленнее из-за запуска отдельных процессов

Задача 2. Параллельный парсинг веб-страниц с сохранением в БД¶

В task2 реализованы:

  • threading_parser.py
  • multiprocessing_parser.py
  • async_parser.py
  • compare.py
  • inspect_database.py

Что делает парсер¶

Каждая программа:

  • получает список URL-адресов
  • делит его на равные части
  • загружает HTML-страницы
  • извлекает содержимое тега <title>
  • сохраняет результат в базу данных
  • печатает обработанные URL и заголовки
  • измеряет общее время выполнения

Как сохраняются данные¶

Используется та же база данных PostgreSQL, что и в лабораторной работе 1.

Результаты записываются в существующие таблицы:

  • users — создаётся или переиспользуется служебный пользователь-парсер
  • trips — создаётся или переиспользуется служебная поездка
  • messages — каждый результат парсинга сохраняется как сообщение

Формат сообщения:

[asyncio] https://www.python.org -> Welcome to Python.org

Переменные окружения¶

Файл task2/.env должен содержать:

DATABASE_URL=postgresql+psycopg2://postgres:0000@localhost:5432/travel_buddy_db
PARSER_USER_EMAIL=parser@travel-buddy.local
PARSER_USERNAME=web_parser
PARSER_TRIP_TITLE=Web parsing results

Проверка базы данных¶

Скрипт inspect_database.py позволяет:

  • проверить подключение к PostgreSQL
  • вывести количество записей в таблицах
  • увидеть пользователя-парсера
  • увидеть служебную поездку
  • просмотреть сообщения, созданные во время парсинга

Наблюдение по результатам¶

  • asyncio показал лучшее время на сетевом парсинге
  • threading также работает эффективно для I/O-bound задач
  • multiprocessing оказался самым медленным из-за накладных расходов на процессы
